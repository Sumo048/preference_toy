cells (`explore/E1/run_baselines.sh`, `results/baselines.json`). D = `tv_to_ideal`, Removed = 1 − `neg_mass_ratio`,

## What the edit is

The edit adds gated paths beside the output layer `out` of π_ref's velocity net. The original weights do not change.

- **One gated path per bad behaviour.** Each path has a linear detector: a logistic probe on block 2's SiLU hidden
  `blocks.2` fc1 output (128), plus x_k (2) and the 16 Fourier features of c. A second linear threshold on t
  restricts the path to steps 0–9 (t > 0.525). The gate is hard (0/1). The four per-behaviour detectors are OR-ed.
- **128 SiLU units per path** read the same feature vector. Their 2-d output is added to the velocity.
  The output is exactly 0 when the gate is off (the identity test passes bit for bit; see `test_identity.py`).
- **Two recursive rounds.** Round 2 fits a new gated path on the round-1 policy.
- Size: 38,144 added parameters for 2 rounds (π_ref has 163,458). No original weight changes.

Fitting is label-free and geometry-free (the oracle is used only for evaluation and diagnostics):

1. **Mode tracker** (`common.build_tracker`). A fixed set of 768 noises is decoded by π_ref at 201 conditions.
   At each condition, typical decodes are clustered with toypref's basin rule (kNN typicality, single linkage at
   3× the median 1-NN spacing). Clusters at neighbouring conditions are linked when they share noises. The linked
   clusters form tracks, one per behaviour. Tracks that contain a logged negative are bad. Against the oracle,
   the bad flag has precision 1.00 in every cell. Recall is 0.82–0.87 at the strict radius; the misses are mode
   tails beyond eps, and a 2× radius is used for fitting.
2. **Training set.** 8,192 random (c, ξ) pairs, decoded by π_ref and labelled bad/good by the tracker.
3. **Detectors.** One logistic probe per bad track on the features above, pooled over steps 0–7 of the π_ref
   decode (the label is the final action's track), with threshold p > 0.5.
4. **Rescue targets.** For each bad sample: a hop at its own condition. Along 16 noise directions × 25 radii
   (0.1–2.5), each new good track's first exit is a candidate. The choice minimises noise distance plus a per-track
   price. The prices come from dual ascent so that the good tracks end with equal mass (*balanced exits*).
5. **Unit weights.** Adam on the added units only (1,500 steps of 1,024 samples, lr 1e-3 cosine, gradient-norm
   clip 1), with the gradient through the 20-step Euler decode. Loss: ‖final action − target‖² for bad samples, plus 4 × ‖final action − π_ref action‖²
   for good samples (the hard gate fires on many of them, see below).

## Why it works

- **The network decides early, and its activations show the decision before x does.** A linear probe on the
  block activations separates bad from good trajectories at step 0 with held-out AUC 0.96 (`b2.z`; all layers 0.98).
  On (x, c features) alone the AUC is 0.74 (`results/commit_*.json`). The rescue curve p(k) stays near 0.5 until
  step ≈ 8 and falls below 0.2 by step 10–12 (median k_commit 10.5 on k4 s0, 11.5 on alt s0). So a detector can
  fire at step 0, and a small push in the first steps still has the whole remaining flow to carry it into
  another basin.
- **The gate window should reach k_commit.** With per-track detectors, gate windows of 4, 6, 8, 10 and 12 steps
  give D 0.113, 0.115, 0.110, 0.088 and 0.085 (round 1, k4 s0 n4). The gain comes once the window reaches
  k_commit (≈ 10). Past it, off-mode mass rises (0.040 → 0.046).
- **One detector per bad behaviour.** One mode's noise region at a condition is close to convex, but the union of
  4 forgotten modes is not. At an equal window (steps 0–5, 128 units), per-track detectors cut D from 0.145 to
  0.125 and Collateral from 0.087 to 0.050.
- **Balanced exits drive Collateral.** Collateral is the TV over the renormalised retained modes. If redirected
  mass piles onto the nearest retained neighbour, Collateral rises even when no retained trajectory moves.
  Balanced exits (prices on good tracks) cut Collateral from 0.142 to 0.095 with a single detector. With
  per-track detectors, Collateral is 0.03–0.05 on k4 and ≤ 0.02 on alt.
- **The tracker turns a few negatives into labels over all c.** One logged negative per forgotten mode is enough
  to name its track. All fitting data then come from π_ref samples. So npm 4 and npm 16 give *identical* grafts
  (same tracks, same training streams). This is the main reason the graft beats B1a, which only trains near the
  logged conditions. B1a's `neg_still_forget_far` is high: it forgets far from the negatives' conditions.

## Measurements that made the edit easy to design (candidate Phase 4 tools)

1. **Behaviour tracker / basin continuation across c** (from π_ref samples and the logged negatives only). It gives
   label-free bad/good labels for any (c, action). The surgeon can build it in the sandbox. A `tracks` tool would
   return, for a cluster, its track's mass per c-bin and its neighbours.
2. **Probe AUC by step × layer** (`contrast` in PLAN 6.5 is this, per step). It showed that block-2 hidden at step 0
   already separates (0.96). That fixed both the detector layer and the start step.
3. **Rescue curve p(k) and k_commit** (the branch tool). This fixed the gate window: up to about k_commit.
4. **Residual decomposition after an edit** (`diag_resid.py`): forgotten mass whose gate never fired vs whose gate
   fired but the redirect failed, plus the gate firing rate on retained trajectories. It showed detection is not
   the bottleneck (misses 0.001 of the mass). The redirect is: 0.06 of the mass fired and still failed. It also
   showed that the OR of gates over 8 steps fires on 62% of retained trajectories and flips only 0.5%: the stay-put
   loss gives the locality, not the gate. A quick_check variant should report this firing rate.
5. **Good-basin fill after the edit** (label-free, from the tracker): it predicts Collateral before any oracle call.

## What failed or did not help

- A single detector for all forgotten modes: D 0.145–0.182 vs 0.110–0.125 with one per track.
- A stricter detector (p > 0.8): fewer false fires (step-0 FPR 0.07 → 0.02), but TPR fell to 0.66 and round 1
  D rose 0.110 → 0.133.
- Graft into the residual stream after block 2 instead of the velocity: D 0.129 vs 0.110, Collateral 0.083 vs
  0.032 (config F otherwise).
- More capacity (256 units, 3,000 steps): D 0.108 vs 0.110. Capacity is not the limit.
- A gate window past k_commit (12 steps): no gain, more off-mode mass.
- The first full sweep (K10, lr 3e-3, no clip) diverged on seed 4 (see Results). Fixed by clipping and a lower lr.
- alt Removed saturates at ≈ 0.83: each forgotten mode sits between two retained ones, and exits near the
  boundary end between modes or stay bad. Round 2 adds only 0.01.
- **Bug, fixed:** an early version cached the c features in the hook by `id(c)`. Python reuses ids, so grafts could
  read stale features. All results from before the fix are in `explore/E1/results/invalid/` and are not used.

## Caveats

- Outside the claims (Amendment 1). Seeds 0–4 only. Two settings.
- The fit uses many π_ref decodes: about 1.5 M for targets, 150 k for the tracker, and 20-step backprop through
  π_ref for 2 × 1,500 batches of 1,024. These are CPU only, but far more than a gate budget would count.
  The run time per cell is ≈ 10–20 min on 1 core.
- The edit is large (+23% parameters) because w_in is dense. Smaller grafts were not explored.
- The approach leans on two toy properties: behaviour identity is continuous in c, and each forgotten mode has
  at least one logged negative. With a forgotten mode that has no negative, the tracker cannot name it.
