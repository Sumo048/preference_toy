toypref · preference editing on a 2-D flow policy

Toypref Method Map

This page shows every setting we tested. For each setting it shows how each method performs. All settings in one grid show the same list of methods.

We train a flow policy on 8 modes that sit on a ring. A mode is one behaviour. We then edit the policy to forget some modes. The other modes are retained. A setting is one data situation. A method is one family of algorithms. A config is one method with fixed hyperparameters and add-ons.

P+N
The method uses positive labels and negative labels.
P
The method uses positive labels only.
N
The method uses negative labels only.
U
The config also uses unlabelled samples from the base policy. These samples need no label.
■ Removed
The share of the base policy's mass on forgotten modes that the edit removes. 100% means fully forgotten. Higher is better.
■ Collateral
The change to everything else: the total-variation distance between the edited and base policies over retained modes plus the region between modes, each renormalised. 0 means no change. Lower is better.

How we pick the method list. For each method and each setting, we select the config with the lowest distance to the ideal. The ideal policy puts equal mass on each retained mode, and no mass on forgotten modes or between modes. Each grid then shows every selected config in every setting. A config is a candidate only if it ran in every setting of its grid.

Fresh-seed results

Each grid has a toggle for seeds 5–9. The section Pre-registered tests lists every test we fixed before we saw the fresh seeds, and its outcome.

Grid 1: unconditional toy

The policy has no condition. All logged negatives of a mode share the same input. Positives exist in every setting: 512 positive samples unless the setting says otherwise. A method may use them or ignore them.

Each setting uses 1, 4 or 16 negatives per forgotten mode. The base settings use one count of forgotten modes. The other settings pool 1, 2 and 4 forgotten modes.

Grid 2: conditional toy

The policy takes a condition c in [0, 1). The ring rotates by 1.5 mode spacings and grows as c grows. Every logged sample has its own condition. No two negatives share a condition. This is the practical case for a robot policy.

This grid has no positive labels. Every method is a negatives-only method. Each setting uses 1, 4, 16 or 64 negatives per forgotten mode.

We fixed each test before we ran the fresh seeds 5–9. A test passes when the method beats the comparator by more than 2 standard errors, paired over seeds and negatives-per-mode values, and no other arm dominates it. The score is the distance to the ideal. Lower is better.

Self-paired DPO: results and controls

Self-paired DPO is the user's idea. It pairs each logged negative with a fresh π_ref sample at the same state, used as the winner. We tested it in every earlier setting of both toys, plus controls that isolate each part of the loss.

Unconditional toy. Fresh noise with β = 1 is the strongest method that uses only the negatives (no unlabelled anchor) at 2 and 3 forgotten modes. It beats NPO-negatives-only by 0.11 to 0.14 (lower in 28 to 30 of 30 paired runs), and it beats Ours in every setting. At 1 forgotten mode it ties NPO. At 4 forgotten modes near-nf rerouting wins (0.180 against 0.374). The anchored KTO stays best overall.

Conditional toy. It beats NPO-negatives-only and Ours in most settings. It never beats the round-3 recipe, and it never beats tracking.

What the controls show. The ungated push destroys the policy. The gate makes the push safe, but only when it closes early (fixed β = 25). A calibrated, later-closing gate (βH = 1, 3, 10) does worse. The gated push beats plain hop only at 1 forgotten mode. At 4 forgotten modes it adds off-mode mass and loses. BC on the hop winners alone collapses the map.
